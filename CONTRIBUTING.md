# Contributing to Agent Software Testing results

This repository holds the **results** of Agent Software Testing: for each run of each system on each program, the set of covered
branches, a coverage curve, a few derived tables and counts of sanitiser findings. The standard (specification, runner,
program definitions) is in the `agent-software-testing` repository; the website is generated from this repository by
`agent-software-testing-site`.

Everyone who takes part follows the [Code of Conduct](CODE_OF_CONDUCT.md). Bugs found in the 18 programs are
handled under [DISCLOSURE.md](DISCLOSURE.md).

## Ways to take part

| You want to | Do this |
|---|---|
| Add your tool's results | Follow [docs/SUBMITTING.md](docs/SUBMITTING.md) and open a pull request that adds `submissions/<system_id>.json`. A maintainer approves it, the bundles are replayed by a workflow and a maintainer adds the runs. |
| Report a wrong or mislabelled number, a missing run, a broken file or a wrong description | Open a **Data issue**. Say which file and which row and how you checked. |
| Improve the scripts or the documentation | Open an issue or a pull request. |
| Report a problem with the runner, the specification or a program definition | `agent-software-testing` repository. |
| Report a problem with the website | `agent-software-testing-site` repository. |
| Report a bug you found in one of the 18 programs | See [DISCLOSURE.md](DISCLOSURE.md). Reports go to each project's maintainers through the project's own reporting channel. |

## What lives here and who changes it

* `programs.csv`, `systems.csv`, `runs.csv`, `sets/`, `curves/`, `universe/` and `RELEASE.json` are **data**. They come
  from replays and they change only through a pull request that a maintainer prepares from a replay (for example, from
  a submission pull request) or to correct an error.
* `derived/` is generated by `scripts/derive.py` from the data above. **Never edit a derived file by hand**; change
  the data or the script and run the script again.
* `scripts/derive.py` and `scripts/check.py` need only this repository and the Python standard library.
* **A published release does not change.** Once a release is tagged and archived, its files are not edited. A correction
  is made in the next release and listed in its errata, with the release it replaces. A pull request that edits a
  tagged release will be asked to become an erratum.

The data is licensed under CC BY 4.0 (`LICENSE-DATA.md`) and the scripts under Apache-2.0 (`LICENSE`). By contributing
you agree that your contribution is licensed that way: data under CC BY 4.0, scripts under Apache-2.0.

## Setting up

You need Python 3.10 or later. Clone this repository **next to** the runner repository (`agent-software-testing`), so that the checks can compare `programs.csv` with the program definitions:

```
workspace/
  agent-software-testing/
  agent-software-testing-results/
```

Then, from the root of this repository:

```
python scripts/derive.py      # regenerate derived/ and the systems table in README.md
python scripts/check.py       # run every check; exit status 0 when they all pass
```

`check.py` verifies, among other things, that the tables have the columns the specification gives; that `programs.csv`
agrees with the program definitions; that every universe and branch set is well formed, sorted and consistent with
`runs.csv`; that every covered branch belongs to the universe of its program; that every curve is complete and
non-decreasing; that the derived tables equal a recomputation; that the derived signature counts hold
only counts; and that the release file agrees with the tables.

## Rules for data and for scripts

* **Counts only for sanitiser findings.** `derived/signatures.csv` holds the number of distinct signatures by system,
  program, sanitiser and error class. No frames, function names, file names, stack traces, inputs, case hashes or
  descriptions of causes, anywhere in this repository (`SPEC.md` section 8, `DISCLOSURE.md`).
* **Branch sets hold only branch identities** (`file:line:block_id:branch_id`), never test cases or inputs.
* **No personal data.** No names, email addresses, user or host names or local paths in any file. Contact details stay
  in the pull request discussion; a manifest holds only a GitHub handle.
* **Every number has a measure.** A run says whether it was measured as `canonical`, `standard`, `common-observer` or
  `published` and tables say track, budget, cores and number of repeats for each system. Do not mix measures silently.
* **Scripts** use only the standard library, start with the copyright and SPDX lines
  (`# SPDX-License-Identifier: Apache-2.0`, `# Copyright 2026 The Agent Software Testing authors`) right after the `#!` line and are
  deterministic: the same inputs give byte-identical outputs.
* **No hand-made data.** If you cannot say which replay produced a number, it does not belong here.

## Pull requests

1. Open a pull request against `main`. Describe what changes and why, link the issue for a correction (the Data issue)
   and say which files were regenerated. A submission pull request adds only `submissions/<system_id>.json`.
2. Run `python scripts/derive.py` and `python scripts/check.py` and say that you did. A pull request that does not pass
   `check.py` is not merged.
3. A submission pull request is replayed by a workflow after a maintainer approves it
   ([docs/REPLAY-WORKFLOW.md](docs/REPLAY-WORKFLOW.md)). The runs are added in a follow-up pull request by a
   maintainer and carry the replay evidence (bundle hashes, runner version, image identity, the flake check and the
   manifest in `submissions/`). The submitter reviews it.
4. A pull request that corrects a published number adds an entry to the errata of the next release and states which
   release is wrong.
5. A maintainer reviews and merges.

## Large files

Branch sets are gzip-compressed JSON and are written by scripts. Do not reformat, re-compress or re-sort them by hand
and do not commit generated files that are not part of the layout in `README.md`.
